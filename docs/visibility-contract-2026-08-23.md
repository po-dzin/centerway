# Контракт видимості платформи — 2026-08-23

SEO / GEO / AEO для `www.centerway.net.ua`. Що змінилось, звідки тепер береться
опис бренду і що перевіряти перед публікацією.

## Що було

- Жодного `application/ld+json` на всій платформі. Машина не могла дізнатись, що
  CenterWay — організація, що Євгеній Корякін — автор, що «Шлях 21» — курс за
  4 100 ₴. Пошук це переживає, генеративна відповідь — ні: вона цитує те, що
  сказано прямо.
- Тридцять блоків `export const metadata`, кожен зі своїм суфіксом
  (`- CenterWay`, `| CenterWay`, `CenterWay |`, нічого) — для видачі це чотири
  різні бренди.
- Дефолтний опис у root-лейауті: «Unified platform for CenterWay products» —
  англійською, внутрішньою мовою, і саме він діставався кожній сторінці без
  власного опису.
- `/programs/reset-day` не було в sitemap; курсів із білдера там не було взагалі,
  хоча їхні офер-сторінки вже публічні.
- Немає `/llms.txt`.

## Формат опису

Один порядок для будь-якого публічного опису:

**ЩО це · ДЛЯ КОГО · ЩО ВСЕРЕДИНІ · ДЕ МЕЖА МЕТОДУ.**

Межа — не декор. Матриця заявлень у бренд-контракті забороняє медичні обіцянки,
а асистент, що переказує велнес-сайт, — саме той читач, який перетворить «детокс»
на медичну заяву. У meta-описі стоїть коротка форма (`boundaryShort`), у
структурованих даних і `/llms.txt` — повна (`boundary`).

## Джерела

| Що | Де |
| --- | --- |
| Бренд, позиціонування, межі, автор, контакти | `src/lib/brand/identity.ts` |
| Збірка метаданих сторінки (title / description / canonical / OG) | `src/lib/seo/metadata.ts` |
| Вузли структурованих даних | `src/lib/seo/jsonLd.ts` |
| Рендер графа в HTML | `src/lib/seo/StructuredData.tsx` |
| Відповідь для асистентів | `src/app/llms.txt/route.ts` |
| Карта сайту (статичне дерево + опубліковані курси) | `src/app/sitemap.ts` |

Сторінка більше не пише суфікс бренду: його додає `title.template` у
`src/app/(platform)/layout.tsx`. Сторінка вирішує лише свій опис — і пише його у
форматі вище через `describe()`.

## Граф структурованих даних

Один граф зі стабільними `@id`, а не купа незалежних заяв:

- `#organization` — `Organization` + `EducationalOrganization`, у кожній сторінці
  showcase-лейауту;
- `#website` — `WebSite`, видавець — організація;
- `/expert#person` — `Person`, автор; на `/expert` сторінка ще й оголошує себе
  `ProfilePage` про нього;
- `Course` + `BreadcrumbList` на кожній офер-сторінці (шість рукописних і будь-який
  курс із білдера) — з `ProgramDetailPage`, тому нова сторінка отримує їх без правок;
- `Product` на `/products/**` — **без** `Offer`, поки ціна не узгоджена;
- `ItemList` на `/programs` і `/products`;
- `Service` на `/consult`.

Ціна в `Offer` — це `commerce.amount`, тобто та сама цитована сума, що і в кнопці
(`listAmount`, ніколи не списувана `amount`; див. CW_TEST_PRICE_1UAH у
`src/lib/products.ts`). Сторінка не може надрукувати одну ціну, а опублікувати іншу.

**Чого свідомо немає.** `FAQPage` — жодна сторінка не має справжнього блоку
питань-відповідей, а вигадати його заради rich result — найшвидший спосіб, щоб
розмітку перестали читати. `Review` / `AggregateRating` — відгуки на платформі не
збираються як оцінки.

## Межі індексації

- `my.centerway.net.ua` — `Disallow: /` цілком (`src/app/robots.ts`), плюс
  `noindex` на полиці, курсі, уроці й білдері.
- `/profile` тепер теж `noindex`: без сесії сторінка не каже нічого.
- `/pay/thanks`, `/pay/failed` — `noindex`, в URL номер замовлення.
- Курс із видимістю `unlisted` має сторінку, `noindex` і **не** потрапляє в sitemap.
- `/llms.txt` на персональному хості віддає 404.

## Що перевіряти

```bash
npm run lint && npm run build && npx vitest run
```

Далі на живому дереві: `<title>` без подвійного суфікса, один `ld+json` граф на
сторінку, `sitemap.xml` містить `/programs/reset-day` і кожен `listed`-курс,
`/llms.txt` віддає межі методу до першого оферу.
