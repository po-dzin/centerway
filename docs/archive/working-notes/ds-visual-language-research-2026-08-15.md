Слабые места сегодняшнего набора:
- нет **предметных карточек продуктов** (травяные сборы, комплекты) в едином стиле — на `/products` фото разнородные;
- нет фото **людей в практике** (движение, дыхание — «телесная достоверность» из брендбука); есть только портреты автора;

- нет системы имён/размеров: `v1/v2/v4/v5`, `home-desktop/mobile`, `card`, `hero` — форматы не зафиксированы.

## 2. Целевая система изображений (4 роли + 2 варианта фона)

| Роль | Формат | Где | Правило |
|---|---|---|---|
| **Backdrop** (фон блока/героя) | 21:9 desktop / 4:5 mobile, тёплый или тёмный | hero платформы, hero сети (dark-photo режим), фон офферных секций | много воздуха под текст; объектов ≤ 3; графика-орбиты допустима, но **не в зоне текста** |
| **Object** (предмет продукта/программы) | 4:5 или 1:1, вырезка на матовом фоне того же цвета, что карточка | карточки программ/продуктов, `/products/*` | один объект + одна травяная деталь; тень мягкая, направление света одно на весь набор |
| **Practice** (человек в практике) | 3:2 / 4:5 | how-it-works, method, expert, way21 фазы | без лица крупно, без «йога-стока»: руки, дыхание, вода, стол, коврик; та же цветокоррекция |
| **Portrait** (автор/куратор) | 4:5 | expert, author-block, consult | уже есть (`curator-photo`, `hero-koryakin`); привести к общей коррекции |
| Варианты | `light` (песок/лён) и `dark` (уголь-зелёный) для Backdrop и Object | dark mode + M-dark | генерируем парами сразу |

Именование: `public/cw/img/{role}/{subject}-{variant}-{ratio}.{webp|avif}` (`backdrop/way21-dark-21x9.webp`, `object/herbs-blend-light-4x5.webp`). Пайплайн: исходник → sRGB-тег обязателен (см. память об iOS-шве) → 2 размера → webp+avif.

## 3. Ручная графика — SVG-язык «путь / орбита / точка»

Из фото и эмблемы уже читаются три примитива:

- **точка** (`dot`) — узел, «где я»;
- **линия/пунктир** (`path`) — маршрут между блоками, «что дальше»;
- **круг/орбита** (`orbit`) — цикл, фаза, «телесный ритм».

Это ровно семантика UI-UX канона (где я / что за шаг / что дальше) — графика становится **навигацией между блоками**, а не декором:

| Паттерн | Применение | Реализация |
|---|---|---|
| section-rail | вертикальная тонкая линия с точками у якорей секций (лендинги сети, длинные страницы) | SVG `<line stroke-dasharray>` + `<circle>`, цвет `--cw-sem-warmth`/`progress`, opacity .35; активная точка = `guide-primary` |
| step-orbit | 3–7 шагов протокола (фазы way21, дни reset-day) как точки на дуге | один SVG-компонент `<Orbit steps={n} active={i}/>` |
| connector | пунктирная дуга между двумя карточками (way21 ↔ reset-day, dosha → результат) | SVG-path, `stroke-dashoffset` анимация при reveal |
| dosha-glyphs | vata/pitta/kapha и пары — три круга разной плотности точек | SVG, монолиния |
| grain | зерно канвы | `feTurbulence` в data-URI, opacity .04–.06, `mix-blend-mode: multiply` (light) / `screen` (dark) |

Правила: монолиния 1–1.5px, скругленные концы, никаких заливок кроме точек, opacity ≤ .5, цвет только из `--cw-sem-*`; в зоне текста графики нет; в `prefers-reduced-motion` анимации `dashoffset` выключены.

## 4. Иконки

Сейчас ~45 ad-hoc inline `<svg>` в TSX + эмодзи в чипах лендингов. Нужен один набор:

- Стиль: **stroke 1.5, 24-сетка, скруглённые концы и углы**, без заливки — тот же монолинейный характер, что ручная графика; в dark цвет наследуется через `currentColor`.
- Состав v1 (~32): маршрут (стрелка, шеврон, «дальше», «назад»), тело/ритм/опора (три знака из тэглайна), день/фаза/неделя, чек/гарантия, время, цена, tg, mail, телефон, вода, трава/лист, чаша, камень, дыхание, сон, еда, движение, вопрос/FAQ, предупреждение-boundary, звезда-proof, пользователь, замок, глобус/язык, тема (солнце/луна), меню/закрыть.
- База: **Phosphor** (thin/light) или **Lucide** как каркас метрики; специфичные (доши, тело/ритм/опора, чаша, камень) — рисуем сами в той же метрике. Не смешивать два набора визуально: единая толщина и радиус.
- Реализация: один `Icon` компонент со спрайтом (`<symbol id>`), для static-лендингов — тот же спрайт как `shared/img/icons.svg`; svgo с нормализацией stroke.

### Грейд «CenterWay v1» — проверен, работает

Рецепт (sharp), даёт матовость и тепло, попадает в палитру ДС:

```
toColorspace(srgb) → modulate({saturation: .80, brightness: 1.03})   // .68 для practice-кадров
→ recomb warm ([1.045,.005,-.02],[0,1,0],[-.03,.01,.955])
→ linear(.93, 14)   // подъём чёрного = матовость
→ gamma(1.02)
```

**Найденный баг пайплайна:** `sharp.withIccProfile('srgb')` **не переносится в webp** — на выходе файлы без ICC, т.е. воспроизводится ровно тот iOS-шов из памяти проекта. Обязательный финальный шаг:

```bash
webpmux -set icc "/System/Library/ColorSync/Profiles/sRGB Profile.icc" in.webp -o out.webp
```

Проверка — `webpmux -get icc file.webp` должен отдавать профиль. Это надо зашить в будущий `scripts/img/`.

## 5b. Иконки — ответ по «полуручному этно» (проверено рендером)

Готовой библиотеки в нужном характере нет: Phosphor/Lucide/Iconoir — чистая геометрия (холодновато), а «hand-drawn» наборы (Open Doodles и родня) — скетчево и несерьёзно, ломает «премиальность без показной роскоши» из брендбука.

**Найденное решение — гибрид, и он работает:** геометрическая база + SVG-фильтр `feTurbulence` + `feDisplacementMap`, дающий контролируемую «дрожь руки», одинаковую для всего набора. Тест: `ds-icon-character-study-2026-08-15.html` (4 ряда × 11 глифов + ручная графика).

| Пресет | baseFrequency / scale | Как читается |
|---|---|---|
| base | — | чистая геометрия, «как у всех» |
| hand1 | .03 / 1.4 | чуть тёплое, почти незаметно |
| **hand2** | **.05 / 2.4** | **этно-рука: контур живой, читаемость целая — рекомендую** |
| hand3 | .08 / 3.6 | начинает разваливаться на `water`/`kapha` |

Почему это лучше рисования вручную: 32 глифа получают **один и тот же** характер (человек так не нарисует), характер параметризуется одним числом, база остаётся редактируемой геометрией, и тот же фильтр ложится на ручную графику dot/path/orbit — иконки и графика становятся одним почерком.

Практика: фильтр **запекать** в пути на сборке (svgo + прогон через headless-браузер), а не считать в рантайме — иначе Safari платит за фильтр на каждой иконке и мелкие глифы мылятся.

База метрики: **Phosphor Light** (24-сетка, stroke 1.5, скруглённые концы) — из открытых наборов ближе всех к монолинии. Этно-специфика (доши, тело/ритм/опора, чаша, камень) рисуется своя — в тесте они уже намечены.

## 5d. Мультипровайдеры генерации — сверено с рынком на 2026-08

Вопрос «есть ли OpenRouter-подобное для картинок» — да, и таких теперь два уровня: агрегаторы-шлюзы (один ключ → много моделей) и хостеры моделей.

| Вариант | Что даёт | Под нашу задачу |
|---|---|---|
| **Vercel AI Gateway** | Проект **уже на Vercel**: ключ через `vercel env`/OIDC, биллинг в существующем аккаунте, новых вендоров заводить не надо. Модели: Nano Banana Pro / 2 (`google/gemini-3-pro-image`, `-3.1-flash-image-preview`), Flux 2 Pro/Flex, Flux Kontext Max/Pro (`bfl/*`), Imagen 4 (`google/imagen-4.0-*`), GPT Image 2, Grok Imagine, Recraft. AI SDK — уже домашний паттерн проекта | **рекомендую как основной** |
| **OpenRouter Unified Image API** | Запущен в конце июня 2026: один эндпоинт `POST /api/v1/images`, 30+ моделей от 8 провайдеров, capability-discovery API. Ключевое для нас: **`input_references`** (референсные картинки прямо в запросе — URL или base64), **`seed`** для воспроизводимости, `aspect_ratio`, и **`output_format: svg`** (Recraft) | **сильный второй** — форма API буквально под «серия по референсу»; `svg` интересен для иконочного трека |
| **fal.ai / Replicate** | Хостеры моделей: широкий каталог, апскейлеры, нишевые модели, per-second биллинг | как запасной, если понадобится модель, которой нет в первых двух |
| **Midjourney** | Лучшая стилевая консистентность серии (`--sref` / omni-reference), но **API нет** | ручной флоу, только под разовую библиотеку фонов |

Нюанс по референсам, который стоит знать заранее: у AI Gateway текст→картинка идёт через `generateImage`, а **правки по референсу** («тот же кадр, но темнее / другой ракурс») — через `generateText` с мультимодальной моделью (Nano Banana Pro), где референс передаётся частью сообщения. У OpenRouter это одна форма запроса — `input_references` в том же вызове. Для нашего сценария (серия backdrop-ов, привязанная к `dosha-hero-v1`) вторая форма удобнее, но разница в удобстве, а не в возможностях.

Деньги роли не играют: рынок 2026 держится в диапазоне ~$0.002–0.06 за кадр (GPT Image 2 ~$0.002–0.003, Imagen 4 $0.02–0.06, Flux 2 Pro ~$0.02, Nano Banana Pro дороже). Нам нужны десятки кадров, а не тысячи → весь трек это единицы долларов. Выбор делается по трению, а не по цене.

**Вывод:** ставим `scripts/img/generate.mjs` на **Vercel AI Gateway** (нулевое трение: ключ уже есть, вендоров не плодим, AI SDK в доме), а **OpenRouter** держим как второй адаптер в том же скрипте — включаем, если упрёмся в референсы/`seed`/`svg`. Скрипт с самого начала пишем провайдеро-агностично: на выходе всегда общий грейд + `webpmux -set icc`, чтобы генерённое и снятое проходили один пайплайн.

## 6. Референсы (направления, не для копирования)

- **Тактильное стекло с теплом**: Apple Liquid Glass / visionOS (иерархия материалов, но у нас — матовое и тёплое, не прозрачно-глянцевое); Linear / Arc — сдержанное стекло chrome.

- **Ручная монолиния как навигация**: редакционные лонгриды с progress-rail (NYT/The Pudding), медитативные приложения с орбитами шагов.
- **Аюрведические бренды**: Sahajan, Ranavat, Fable & Mane — как выглядит «премиум без показной роскоши» в этой нише; смотреть на предметную съёмку.
