# Конверсионные journey: что уже есть и как это складывается

Дата: 2026-09-05
Статус: карта, не реализация. Инвентарь снят с кода на ветке `feat/full-photo-crop`.
Продолжает: `docs/landing-funnel-network.md`, `docs/dosha-test-audit-2026-09-04.md`,
`docs/platform-pay-confirmation-2026-08-21.md`, `docs/pay-pending-state-2026-09-02.md`.

Задача этого документа: не придумать новые воронки, а собрать существующие слои в
сквозные маршруты человека и назвать места, где маршрут рвётся. Разрывы ниже — это
и есть план.

## 2. Journeys, собранные из этих слоёв

Обозначения: `[ok]` — переход существует и работает; `[gap]` — перехода нет или он
ведёт в никуда; `[manual]` — переход делает человек руками.

### J1. Холодный → тест доши → консультация / Шлях 21

Основной маршрут сети. Тест — единственный бесплатный вход с результатом.

```
реклама / поиск / главная
  → dosha.centerway.net.ua  или  / (герой → «пройти тест»)        [ok]
  → /dosha-test (аноним, черновик, резюм)                          [ok]
  → результат: тип + уверенность + два выхода                       [ok]
     ├─ «Отправить в Telegram» → бот → customers.tg_id + теги        [ok]
     ├─ «Сохранить в кабинет» → Google → attach → теги              [ok]
     ├─ consult?dosha=X → лендинг открывается с эхо результата       [ok]
     │     → лид-форма (имя/тел/email заново) → leads + TG-группа   [ok]
     │     → «мы свяжемся»                                          [manual]
     └─ way21?dosha=X → лендинг → чекаут 4100 / заявка 9000         [ok]
  бросил тест на середине
     → job dosha:reminder (15 мин, 24 ч) → счётчик++ и событие      [gap: ничего не отправляется]
  завершил, никуда не пошёл
     → ничего                                                       [gap]
```

Где рвётся:

- **Напоминание о незавершённом тесте — призрак.** `processDoshaReminderJob`
  увеличивает `reminder_sent_count`, пишет `dosha_reminder_sent` и **никому ничего
  не шлёт**: у анонимной сессии нет адреса. Крон `cw-dosha-reminders` каждое утро
  честно отрабатывает пустоту, а аналитика видит «отправлено».
- **Результат в Telegram — тупик.** `doshaResultOutro` говорит «сохранили», и всё.
  Ни консультации, ни Шляха 21, ни «через 3 дня напомним». Человек дал нам единственный
  канал, куда мы умеем писать, и мы им не пользуемся.
- **Consult просит контакт заново.** Эхо результата на лендинге есть, но форма не
  знает, что человек только что был у нас, и не может предзаполнить ничего, кроме
  `utm_content`.
- **Завершил тест и ушёл** — ни одного касания. Это самый большой сегмент по логике
  любой викторины и он полностью тёмный.

### J2. Холодный → Reset Day (795) → курс → Шлях 21

Низкий порог. Единственный journey, где апселл прописан в контенте.

```
реклама → resetday.centerway.net.ua → чекаут (email/тел)            [ok]
  → WayForPay → /pay/thanks «Перейти до курсу»                       [ok]
  → письмо с ссылкой /learn/reset-day                                [ok]
  → вход Google тем же email → linkPurchases → полка                  [ok, хрупко]
  → не открыл: нудж 1 и 2 в Telegram                                  [ok, только если tg_id]
  → уроки, «Урок пройдено», день N в Telegram                         [ok]
  → последний урок: FAQ-ответ со ссылкой /programs/way21              [ok, слабо]
  → курс пройден целиком → ничего                                     [gap]
```

Где рвётся:

- **Конец курса не существует как экран.** Прогресс 6/6, у последнего урока нет
  «далее». Событие `course_completed` не эмитится, напоминание не запланировано,
  кабинет не меняется. Апселл на way21 живёт внутри одного FAQ-аккордеона.
- **Другой email при оплате → «Не бачу доступ».** `linkPurchases` матчит только
  верифицированный email аккаунта. Бот-ответ `cabinet` прямо предупреждает об этом,
  то есть проблема известна и решена копирайтом.
- **Напоминания идут только в Telegram.** Покупатель оставил email в момент оплаты,
  но `notifyLearner` умеет только `tg_id`. Не подключил бот — не получит ни одного
  нуджа, хотя канал в базе лежит.

### J3. Холодный → Шлях 21 (4100 / 9000)

Ядро по выручке.

```
реклама → way21.centerway.net.ua
  → «Почати» → #offer → .openModal → /api/pay/start?product=way21    [ok]
  → «Супровід 9000» → лид-форма → leads + TG-группа                   [ok] → [manual]
  → оплата → thanks → письмо → /learn/way21 → день N                  [ok]
  ← из reset-day (контент), из consult, herbs (ссылки)                [ok]
  ← из теста доши                                                     [ok]
  → в тест доши                                                       [gap]
```

Где рвётся:

- **Way21 говорит о доше пять раз и не даёт ссылку на тест.**
  `landing-funnel-network.md` утверждает, что «way21 links to the test from its
  method section»; в HTML ссылки нет. Человек, который сомневается (а страница сама
  говорит «протокол под вашу дошу»), не получает бесплатного шага.
- **Заявка на 9000 и лид consult — один и тот же тупик**: сообщение в группу и
  «мы свяжемся». Нет автоответа, нет ссылки на бот, нет статуса в админке.

### J4. Лид (consult / way21-support / herbs) → сделка

```
форма → POST /api/leads → leads (дедуп 2 мин) + TG-группа + fbq Lead   [ok]
  → «Дякуємо! Ми зв'яжемось»                                            [ok]
  → человек закрывает вкладку                                           [gap]
  → фаундер пишет в Telegram/звонит                                     [manual]
  → оплата? вручную через админку «ручная продажа»                      [ok, manual]
```

Где рвётся:

- **Лид не становится customer.** `/api/leads` не трогает `customers`; лид с телефоном
  и email не сшивается с тем же человеком, который прошёл тест (tg_id) или потом
  купил (order). Три записи, три личности.
- **У лида нет стадии.** В админке есть `customers`, `orders`, но лиды видны только в
  Telegram-группе. «Ответили / договорились / оплатил / отказ» — нигде.
- **Нет второго касания.** Если фаундер не ответил за день, лид остыл. Ни письма
  «получили, вот что будет дальше», ни ссылки «пока ждёте — вот бот / вот тест».

### J5. После покупки (общий хвост J2/J3)

```
paid → email-чек (Resend) → thanks-кнопка → /learn                     [ok]
  → «Подключить Telegram» в кабинете → tg_id                            [ok, необязательно]
  → нуджи неначатого, день N                                            [ok при tg_id]
  → курс пройден → ничего                                               [gap]
  → срок доступа истёк (expires_at) → ничего                            [gap]
  → herbs как «путь выпускника» → ссылка только с лендинга way21        [gap]
```

- **Выпускник — самый тёплый сегмент, и у него нет ни одного триггера.** Ни экрана,
  ни письма, ни предложения (herbs, consult, повтор через полгода).
- **Herbs без цены → форма**, это осознанно (`herbs-no-price-no-checkout`). Но и
  форма никак не связана с тем, что человек — выпускник way21: `product_code: herbs`,
  и всё.

### J6. Short / IREM (изолированный автор)

```
reboot / irem лендинг → чекаут → thanks «Открыть бот» (?start=токен)   [ok]
  → бот: доступ                                                          [ok]
```

Никаких пересечений с сетью платформы — это инвариант, не разрыв. В этой карте
фигурирует только чтобы не забыть: любой «общий journey-движок» обязан уважать
`carriesDoshaContext`-подобную изоляцию и здесь.

## 3. Разрывы, собранные вместе, по цене починки

Один и тот же паттерн повторяется во всех journey: **система умеет реагировать на
действие, но не умеет реагировать на его отсутствие.** Оплатил — письмо. Нажал —
переход. Ушёл, бросил, закончил, промолчал — тишина.

### P0. Провода, которые стоят по полдня и закрывают дыры в живом трафике

1. **Way21 → тест доши.** Одна ссылка в секции метода. Документ уже считает, что
   она есть.
2. **Успех лид-формы → ссылка на бот** («поки чекаєте — тут відповіді на питання і
   доступ»). Форма уже показывает `lead-modal__done`; добавить один `<a>`. Бот
   получает tg_id, а лид — второй канал.
3. **Результат в Telegram → следующий шаг.** `doshaResultOutro` + две inline-кнопки
   (consult с `?dosha=`, way21). Тот же `doshaResultCopy.ts`, экран и чат остаются
   синхронны.
4. **Doshа-напоминание: доставлять или выключить.** Сейчас крон врёт аналитике.
   Честный минимум: слать через `notifyLearner` тем, у кого есть `tg_id`
   (сохранили в Telegram и бросили при повторе), остальных не считать
   «отправленными».
5. **Экран завершения курса.** Последний урок + все пройдены → «Курс пройдено» с
   одним следующим шагом из данных курса (reset-day → way21; way21 → herbs/consult).
   Эмитить `course_completed` в `events`.

### P1. Нервная система: один адресат, два канала, одна очередь

6. **`notifyCustomer` вместо `notifyLearner`.** Адресат — `customers`, не
   `auth_user_id`. Каналы: Telegram (есть), email через Resend (шаблон чека уже
   задаёт регистр «ви»). Правило выбора: tg_id → Telegram, иначе email, иначе
   `undelivered`. Это разблокирует нуджи для всех, кто не подключил бот, и
   вообще любую последовательность ниже.
7. **Лид → customer.** `persistLeadBestEffort` пишет/обновляет `customers` по
   email/phone (тот же `upsertCustomer`, что в вебхуке) и вешает тег
   `lead_<product>`. С этого момента тест, лид и покупка — один человек.
8. **Последовательности как jobs**, тем же `jobs` + `worker` + pg_cron:
   - `dosha:completed_no_action` — 24 ч после результата без клика по выходу →
     одно касание (consult/way21 по типу и уверенности);
   - `lead:received` — сразу: автоответ «получили, вот что дальше» + ссылка на бот;
     через 48 ч без стадии — второе касание;
   - `course:completed` — сразу: экран; через 1–3 дня: следующий шаг в канал;
   - `enrollment:expiring` — за N дней до `expires_at`.
   Каждая — один хендлер в `worker.ts`, один тип, одна строка в `cron.job`.
   `lms_unstarted_reminders` уже показывает форму: таблица-клейм на
   (ключ, номер касания, канал), чтобы не слать дважды.

### P2. Управление и измерение

9. **Стадии лида в админке.** `leads.stage` (new / contacted / agreed / paid /
   lost) + колонка в `/admin/customers`. Без этого последовательность из п. 8 не
   знает, когда остановиться.
10. **Journey-вью в аналитике.** Одна витрина по `customers.id`: тест → лид →
    заказ → курс → выпуск, с датами. Данные для неё появятся после п. 7.
11. **A/B на лендингах.** Движок есть, к статике не подключён. Отдельная тема;
    трогать только когда есть чем и на чём измерять.

## 4. Что намеренно не предлагается

- **Не CRM и не внешняя рассылка.** `customers` + `jobs` + Resend + бот покрывают всё
  из списка; новая система — это новый разрыв.
- **Не универсальный «журнал journey»** до п. 7: пока лид, тест и заказ — три
  личности, любая витрина покажет три воронки вместо одной.
- **Не кросс-линки с Short/IREM** и не доша-контекст на чужих экспертах: инварианты
  из `landing-funnel-network.md` и `doshaRouting.ts` остаются.
- **Не новый вопросник теста (P2 из аудита доши)** — это про качество результата,
  не про journey.

## 5. Порядок

P0 целиком одной веткой: пять правок, ни одной миграции, эффект на живом трафике
сразу. Потом п. 6 и 7 вместе (они и есть «нервная система»), потом
последовательности по одной, начиная с `lead:received` — он про деньги, которые уже
пришли в форму.
